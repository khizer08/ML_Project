# Project Summary: Web-Based Weather Predictor

The project is a full-stack web application that predicts temperature based on user-provided weather data. 
It uses a machine learning model trained on historical weather data to make these predictions in real-time.

---
## Application Architecture

The final application uses a **microservice architecture**, which means it's split into two separate servers that communicate over a network. 
This is a robust and modern design.

1.  **Frontend & API Gateway (Node.js/Express.js)**: This server is the "user-facing" part.
    * It serves the **HTML, CSS, and JavaScript** files that create the website interface.
    * It acts as a middleman. When a user requests a prediction, this server receives the request and forwards it to the machine learning server.

2.  **Machine Learning Service (Python/Flask)**: This server is the "brain" of the operation.
    * Its sole responsibility is to handle machine learning tasks.
    * It loads the pre-trained model into memory when it starts.
    * It exposes an **API endpoint** (e.g., `/predict`) that the Node.js server can call to get predictions.

---
## The Machine Learning Workflow

This is the core of the project, where we teach the computer to find patterns in data.

#### 1. Problem Framing
The task is to predict a numerical value (temperature) based on a set of known inputs (humidity, wind speed). In machine learning, 
this is a classic **Supervised Learning** problem, because our dataset contains both the input features and the correct output "labels" 
(the actual temperature). More specifically, it is a **Regression** problem, as the output is a continuous value, not a distinct category.

#### 2. Data & Preprocessing
We used a historical weather dataset (`weather_data.csv`). The key columns (or **features**) we used for prediction were **`Humidity`** 
and **`Wind Speed (km/h)`**. The value we wanted to predict (the **target**) was **`Temperature (C)`**.

Before training, the data was cleaned using the `pandas` library in Python by simply dropping any rows that had missing values to ensure 
the model only learned from complete and high-quality data.

#### 3. Model Training & Persistence
* **Train-Test Split**: The dataset was split into two parts using `scikit-learn`. Typically, 80% of the data is used for **training** 
(to teach the model) and 20% is used for **testing** (to evaluate its performance on unseen data).
* **Training**: The chosen algorithm (Linear Regression) was trained on the training data using the `.fit()` method. During this step, 
the algorithm learns the mathematical relationship between the input features and the target variable.
* **Model Persistence**: After training, the "learned" model was saved to a single file, **`weather_model.pkl`**, using the `joblib` library.
 This is a crucial step that allows us to load and use the trained model instantly in our Flask API without having to retrain it every time the 
 server starts.

---
## The Algorithm Explained: Linear Regression

We used **Linear Regression**, one of the most fundamental and interpretable machine learning algorithms.

* **The Goal**: The goal of Linear Regression is to find the best-fitting straight line (or hyperplane in higher dimensions) that describes 
the relationship between the input features and the output target.
* **The Formula**: It learns a simple mathematical equation. For our project, the equation looks like this:

    $$
    \text{Predicted Temperature} = \beta_0 + (\beta_1 \times \text{Humidity}) + (\beta_2 \times \text{Wind Speed})
    $$

    Let's break this down:
    * $\beta_0$ is the **intercept** (or bias). It's the baseline temperature prediction if humidity and wind speed were both zero.
    * $\beta_1$ is the **coefficient** for Humidity. It represents how much the temperature is expected to change if the humidity increases 
    by one unit, assuming wind speed stays constant.
    * $\beta_2$ is the **coefficient** for Wind Speed. It represents how much the temperature is expected to change if the wind speed increases
     by one unit, assuming humidity stays constant.

    The **training process** is what finds the optimal numerical values for $\beta_0$, $\beta_1$, and $\beta_2$ that result in the most accurate
     predictions for the historical data. These learned numbers are what get saved inside the `weather_model.pkl` file.
